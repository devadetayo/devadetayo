I Want to CSS Battle Kyle Cook and Kevin Powell

5–6 min read

2026-10-02

I have a CSS challenge I keep coming back to: I want to build something, then see how it holds up beside the work of Kyle Cook from Web Dev Simplified and Kevin Powell.

They teach and build in different ways, but both make CSS feel like a craft you can keep getting better at. Their work has pushed me to pay closer attention to the details I used to rush past: the layout, the rhythm, the responsive behavior, and the small choices that make an interface feel finished.

I am not saying either of them has agreed to a challenge. This is a challenge I am setting for myself: take an interface idea, build it with CSS, and compare my decisions against the standard their work has helped me imagine.

The point is not to copy a result

A CSS battle can turn into a race to match pixels as quickly as possible. I want to make it more useful than that. I want to understand why a layout works, where the spacing comes from, how it responds when the screen changes, and whether the CSS stays understandable after the first pass.

The screenshot is only the visible part. Underneath it are choices about structure, sizing, alignment, typography, color, and how much the design should change at each breakpoint.

What I want to test

First, I want to work from a clear reference and build the same interface without leaning on a component library. Then I want to check the result at different widths, inspect the awkward spots, and refine the CSS until the page feels deliberate rather than merely close.

I also want to try more than one approach. Grid might make the structure simpler. Flexbox might make a component easier to adapt. A small set of custom properties might keep the spacing and colors consistent. The right answer depends on the interface, and the exercise should help me see those tradeoffs.

After each round, I want to write down what I got wrong, what improved the result, and what I would change if I built it again. That reflection is where the challenge becomes practice instead of just a screenshot.

Why these two?

Kyle Cook’s Web Dev Simplified videos have helped me make web development concepts feel approachable and practical. Kevin Powell has helped me appreciate how much careful CSS can do, especially when it comes to responsive layouts and the details of the browser’s layout tools.

I admire the work they share, and I want to use that admiration as a reason to practice. Their work gives me a high bar to aim at; the actual progress has to come from sitting down, writing the CSS, and being honest about the result.

A challenge I can start today

I do not need an invitation or a perfect setup to begin. I can choose one small interface, build it, share the result, and explain what I learned. Then I can pick a harder one.

So that is the goal: CSS battle Kyle Cook and Kevin Powell in the only way I can control right now—by learning from the standard they set, shipping my own attempts, and getting better with every round.
